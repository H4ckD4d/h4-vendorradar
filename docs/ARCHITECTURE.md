# H4 VendorRadar — Architecture and scale plan

## Implemented in v0.1
- FastAPI REST endpoints with `/v1` prefix and autogenerated OpenAPI.
- SQLAlchemy models; SQLite default for local demonstration. PostgreSQL URL supported via driver, but **no migration process exists yet**.
- API key mapped to a tenant and actor from `H4_TENANTS` environment variable; every domain query includes `tenant_id`.
- Audit log with actor/tenant/action; no raw payload stored in audit.
- Automated API and cross-tenant tests.

## Production blockers (not implemented)
1. OIDC enterprise SSO, actor RBAC, tenant lifecycle, API key hashing and rotation.
2. PostgreSQL schema migrations with Alembic, constraints, indexes, safe backups and restore drills.
3. Separate workers, queue, DLQ, backpressure, idempotency keys and retry policy.
4. Per-tenant rate limits, quotas, metering, plan entitlements and billing integration.
5. Observability (OpenTelemetry), safe logs, traces, alerts and SLOs.
6. Encryption at rest, managed KMS, secrets vault, audit retention and privacy/deletion policies.
7. Penetration testing, abuse tests, security response process, threat model updates and legal review.
8. Load tests, horizontal scaling, cost/performance profiling and disaster recovery.

## Recommended target
CDN/WAF -> API gateway -> horizontally scaled stateless API -> PostgreSQL HA -> Redis/queue -> workers -> object storage (only when applicable). Separate organizational data using explicit RLS policies and automated isolation tests.

## Product boundary
Cadastro, evidências com fontes e avaliação heurística de risco.

**Do not market this starter as enterprise-ready software.**
